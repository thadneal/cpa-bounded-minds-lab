# CPA project handoff summary

## 1. WHUP: the philosophical grammar

**What Holds Under Pressure (WHUP)** is the systems-philosophical source beneath CPA. Its recurring claim is that every local system operates from incomplete information, compresses what it encounters into workable structure, and survives by revising that structure when reality pushes back. Memory is necessarily compressed rather than archival; prediction fills what perception cannot supply; and truth is better understood as constraint that survives distortion, translation, forgetting, conflicting viewpoints, and repeated attempts to route around it. WHUP repeatedly returns to **constraint, recurrence, and cost** as ways the world forces models to become answerable.

A particularly important WHUP idea for the next phase is that no local perspective carries the whole terrain. More reliable structure can emerge where incomplete perspectives remain distinct long enough for their distortions to collide and recurrent constraints to survive the encounter.

In very compressed form:

```text
local incompleteness
-> compression / prediction
-> contact with resistance
-> correction
-> revised structure
-> what continues to hold earns standing
```

WHUP is available in this ChatGPT Project as **What Holds Under Pressure**.

---

## 2. CPA: translating that grammar into an AI proposal

**Columnar Presence Architecture (CPA)** translates WHUP into a proposed architecture for longitudinal, situated artificial intelligence. It is also influenced by Thousand Brains Theory, though CPA is not intended as a biological reproduction. The book explicitly describes intelligence as local compression under constraint, memory as metabolized summary, truth as recurrent resistance under distortion, and development as drift disciplined by correction.

CPA begins with dissatisfaction with the **oracle paradigm** of current generative AI: a powerful system is summoned, produces a completion, and largely leaves the interaction unchanged. CPA instead asks what an architecture would look like if contact actually altered its future cognition.

The important commitments are:

- **Presence as bounded continuity under recursive update.** What happens before should alter what the same or similar present means later.

- **Language as interface rather than cognitive substrate.** Cognitive pressures should exist before they are smoothed into prose.

- **An ecology rather than a sovereign center.** Cognition arises among bounded partial perspectives rather than one process holding the whole state.

- **Columns as developing local model builders.** Their private histories matter, while their public surfaces remain bounded.

- **Sparse participation.** Most cognition should remain dormant when it has no reason to participate.

- **Consequence as developmental pressure.** Correction should alter later readiness rather than merely repair the current answer.

- **Memory metabolism.** Availability, freshness, authority, contradiction, quarantine, consolidation, and retirement should remain distinguishable.

- **Typed coherence and preserved disagreement.** Different forms of warrant or tension should not be flattened prematurely.

- **Peripheral language models/oracles.** LLM-like systems may contribute language understanding, outside knowledge, or a "wisdom chorus," while remaining external to the organism's core developmental cognition.

The CPA book originally contains fairly concrete diagrams and examples of column types. Subsequent experiments made an important correction: many of those structures should be treated as **illustrative hypotheses rather than anatomy that must be installed beforehand**. The stronger current bias is:

> **local simplicity, global surprise**

The mature organization should be allowed to form developmentally wherever possible.

The current CPA book in the Project is **Columnar Presence Architecture v010**. Its technical sections include sense ingress, engine planes, the column boundary, cognitive tick, memory metabolism, and the minimal organism.

## 3. Rust exploration: establish the physical laws of cognition

The Rust effort was the first major engineering exploration. Its purpose became increasingly clear: **make the substrate trustworthy before asking it to become intelligent**.

The Rust reference machine established such things as:

```text
state N
-> bounded local work
-> immutable reads
-> proposed changes
-> deterministic reduction / commit
-> state N+1
```

Important results included:

- bounded cognitive ticks and finite work budgets;

- multiple deterministic generations/micro-rounds inside a logical tick;

- immutable reads followed by deterministic commit;

- sparse scheduling and real dormancy rather than scanning the whole ecology;

- bounded continuations and deferred work;

- column behavior outside the generic engine;

- typed coherence and preserved opposing evidence;

- stable column/relation storage and compact causal ordering;

- immutable sense registration and source provenance;

- payload handling outside hot cognitive packets;

- external tool/consequence return paths;

- developmental traces and memory lifecycle machinery;

- persistence/replay;

- public observation separated from private cognitive state;

- an Observatory protocol and visualization application;

- extensive performance and allocation benchmarking.

The Rust documentation explicitly framed the implementation as a **reference machine for runtime laws**, rather than an attempt to define mature cognitive column types. The experimental ledger is particularly useful because it records the architectural question, mechanism, result, revision, and remaining uncertainty instead of treating every passing test as a discovery.

By the later Rust releases, the runtime had grown through sense ingress, memory mechanics, developmental behavior, model infrastructure, observability, persistence, and larger-scale ecology tests. The v0.29 benchmark artifact is also in the Project and is useful when questions of scale or representation cost return.

### Why we stopped extending Rust

The Rust work eventually became structurally competent enough that a different risk became more important: we were beginning to **declare too much cognition in advance**.

That prompted the temporary .NET pivot.

## 4. .NET Cognitive Development Lab: can organization develop?

The .NET lab deliberately did **not** attempt a C# port of the Rust engine.

Its founding question was:

> **Can useful cognitive organization develop from cheap bounded local hypotheses under recurring pressure, consequence, and scarcity?**

The initial plan explicitly treated Rust as completed foundational research and shifted attention from plumbing toward development.

A major conceptual change was the interpretation of a column. Rather than treating a column primarily as a named cognitive organ, the lab treated it as a **persistent developmental lineage/locality** whose internal model could change:

```text
persistent:
  lineage
  bounded identity
  developmental history
  public boundary

developmental:
  model substrate
  parameters
  traces
  timescale
  recruitability
  relationships
  standing
```

Different model families competed under explicit cost. Residual could be answered by adapting an existing model, replacing/deepening its substrate, recruiting more participants, creating a new locality, or purchasing nothing durable. The architecture was not supposed to decide that placement beforehand.

### Experimental arc

The lab eventually reached **22 protocols**, **32 invariant tests**, and a final **110-history five-seed closing matrix**.

Some important findings were:

- Different environments rewarded different sufficient local model substrates.

- Familiarity by itself was insufficient grounds for sleeping a participant. Dormancy had to be earned from **marginal redundancy**.

- Consecutive residual was a poor birth criterion, while interrupted recurring unresolved cost could justify developmental opportunity.

- Birth and model selection are separate problems.

- Complexity could rationally be placed through parameter adaptation, richer substrate, new locality, or no durable purchase.

- Functional specialization could emerge without giving a new lineage a semantic role such as "source reliability detector."

- Different lived histories caused initially identical organisms to interpret the same present differently, while later shared consequence could bring behavior back together.

- Memory availability, frequency, freshness, standing, and authority are different things.

- Quarantine could preserve representation while removing ordinary authority: **remember without obeying**.

- Corrective/dissenting influence could earn substantial standing and later lose it when the world changed.

- Repeated successful coordination could become cheaper without requiring a central coalition manager.

- Repeated coactivation alone earned nothing.

- Agreement from several descendants of one evidential ancestor deserved less support than convergence reached through independent histories.

- External fallible "oracle" systems could remain outside the organism while the organism learned context-specific, revisable relationships with them.

- Several external oracles could acquire different local standings rather than collapsing into one global trust ranking.

One recurring abstraction emerged across many apparently separate mechanisms:

> **Standing is provisional permission to matter.**

Compute, structure, memory, correction, coalition relations, and external sources all behaved better when their influence had to keep earning itself through consequence.

The result was a qualified answer to the lab's founding question: **yes, useful organization can emerge from relatively generic developmental pressures in these synthetic worlds without preinstalling the semantic role of every participant.**

The lab also preserved failures. Distribution did not become useful merely because it was distributed. Early fixed dissent ceilings suppressed useful correction. Familiarity-only dormancy withdrew still-useful cognition. Short probation could choose a model that later failed economically. Noisy recurrence could produce low-value exploratory structure. These are part of the experimental record rather than results to hide.

# 6. Handoff to the new lab

The completed .NET lab concentrated on development **inside one bounded organism**.

The recommended successor changes the scale:

> **What develops among bounded minds when they can exchange selected public evidence without collapsing their independent interiors?**

The starting constraints should be conservative:

```text
bounded causal execution
finite communication cost
persistent private histories
compact public surfaces
revisable standing
provenance / ancestry separate from agreement
no omniscient shared cognitive center
```

Do **not** begin by copying every controller from the .NET lab. The protocol-specific mechanisms were experimental instruments. Carry forward the principles that survived pressure.

The first research arc should probably investigate:

1. **Local versus shared memory contamination**  
   Can one mind inherit useful structure from another without granting second-hand memory the authority of lived consequence?

2. **Peer disagreement with preserved interiors**  
   Does keeping independent private histories improve correction compared with full-state synchronization?

3. **Developmental versus doctrinal transfer**  
   Compare transferring a final answer/rule with transferring selected developmental episodes or consequence history.

4. **Bounded communication before language**  
   Can low-dimensional typed signals preserve useful disagreement better than immediate linguistic negotiation?

5. **Emergent convention / artificial culture**  
   Can repeated interaction create shared conventions that earn their persistence and remain revisable?

6. **Incomplete epistemic ancestry**  
   Protocol 18 assumed causal ancestry was visible. A harder problem is discovering shared origin when provenance is missing, partial, misleading, or copied across peers.

There are also several unresolved meta-developmental questions worth keeping nearby: how exploration cadence itself should develop; how low-value exploratory lineages and old coalition habits retire; how much developmental inertia long history deserves; and how standing should transfer between organisms without becoming inherited doctrine.

The successor lab should remain an **experimental environment first**. The eventual Rust synthesis should receive only the runtime laws and developmental principles that survive both the single-organism lab and these higher-order multi-mind experiments.
